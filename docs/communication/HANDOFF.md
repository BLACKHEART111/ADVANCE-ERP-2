- `CommunicationModels.kt`: 13 modules, request/choice/prepared DTOs, payment context enum, recipient-safe document fields/rows, Bangladesh/English-digit phone normalization.

Covers invoice, payment, ledger, reminder, delivery, return, exchange, quotation, sales order, PO, packing, supplier payment, statement. Role checks use existing SecurityManager.

- Manifest package visibility for both WhatsApp apps.

### Persistence

- New `CommunicationEntities.kt` + `CommunicationDao.kt`.
- Room v14 → v15, `MIGRATION_14_15`, registered in database builder; five additive tables:
  - `communication_settings`
  - `communication_templates` (module/status/language key)
  - `communication_party_preferences`
  - `communication_snapshots` (module/document key)

- Direct exchange persists safe returned/replacement product names/quantities and payment method in a communication snapshot. Old exchanges without such snapshot remain unavailable, not reconstructed.
- Ledger opening entry now permits signed opening credit when an explicit nonzero master balance supports it (debit/credit split). Existing zero-clamped master and broader opening-balance policy has NOT been comprehensively fixed/tested.
- Removed unused synchronous invoice/payment PDF methods from SalesViewModel; thermal receipt method converted to IO suspend and its screen caller launches coroutine.
